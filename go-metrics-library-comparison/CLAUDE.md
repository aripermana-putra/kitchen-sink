# Claude Code Rules

## Code Quality

- **DRY** — Don't Repeat Yourself. Extract shared logic; avoid duplicating code blocks.
- **KISS** — Keep It Simple. Prefer the simplest solution that works. Do not over-engineer.
- **YAGNI** — You Aren't Gonna Need It. Do not add features or abstractions for hypothetical future requirements.
- **Single Responsibility** — Each function, type, and package does one thing well.
- **Fail Fast** — Validate inputs early, return errors immediately, avoid deep nesting.
- **No Magic Numbers** — Use named constants for non-obvious values.

## Git Rules

- **Never** add `Co-Authored-By`, `Generated by`, or any AI attribution to commit messages.
- **Never** add `🤖 Generated with Claude Code` or similar footers to PRs or commits.

### Branch Naming

| Type | Pattern | Example |
|------|---------|---------|
| New feature | `feature/<short-name>` | `feature/otel-tracing` |
| Bug fix | `fix/<short-name>` | `fix/histogram-labels` |
| Chore / maintenance | `chore/<short-name>` | `chore/update-deps` |
| Documentation | `docs/<short-name>` | `docs/readme-k8s-setup` |
| Refactor | `refactor/<short-name>` | `refactor/extract-handler` |

### Commit Messages — Conventional Commits

Format: `<type>(<scope>): <subject>`

- `feat`: new feature
- `fix`: bug fix
- `chore`: maintenance, dependency updates, build changes
- `docs`: documentation only
- `refactor`: code change that is not a feature or fix
- `test`: adding or updating tests
- `ci`: CI/CD changes

Rules:
- Subject is lowercase, no trailing period.
- Keep subject under 72 characters.
- Use imperative mood: "add support for X", not "added support for X".
- Body (optional) explains *why*, not *what*.

Examples:
```
feat(otel): add histogram buckets for submission duration
fix(hashicorp): correct summary label separator
chore: bump prometheus/client_golang to v1.20.0
docs: document summary vs histogram tradeoff
```
